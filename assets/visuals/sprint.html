Tomorrow starts oriented because today wrote it down.

Founders don't fail from missing strategy; they fail from open loops. Sprint closes them: the session opens by reading the vault, works exactly one roadmap step to done, and closes by rewriting the state on disk. Orientation is the skill's job, never the founder's memory.

Step 0 · standup

The files answer, not the memory

Read in order: the charter, baton.md, the active initiatives in wiki/initiatives/, and any waiting "Needs your call" sections.

Report in at most five lines and propose exactly ONE focus. A menu is a decision pushed back onto the founder.

Every line cites a file or a log row; a fact you cannot source is reported as "not on record", never improvised.

No active initiative is a legitimate first-use state: say so with the file search that proved it, then route to vision or plan.

Two active: take the one baton.md names, else executing over planned, then the most recent Log entry.

Step 1 · the gate

The state decides, not the mood

planned · executingExecute one roadmap step. idea · survivedRoute to plan; BIG ideas face the gauntlet first. reviewed · bankedClosed arcs. Renewed work needs a new idea with reopens:. unknownStop for repair, never guess around it.

An ask that is not on the roadmap gets one line first: it answers a "Not yet decided" item, or it is new scope and routes through plan.

The founder's enthusiasm today does not outrank the gate; the gate is what their enthusiasm hired.

Step 2 · execute

Done is the checkbox's own text

  • One step per session. The urge to start a second one goes into the roadmap, never into the session.
  • The first step on a planned initiative sets state: executing before the work, with updated: bumped.
  • Bigger than one session, so split honestly: finish the session-sized core now, write the remainder as new steps, say so out loud.
  • Founder-only calls go to "Needs your call" and the work continues around them.

Approve and publish steps need content_state plus a checked receipt citing the founder's exact words in raw/inbox/.

Step 3 · close

The close is one transaction

  1. Recheck the completion condition and its evidence, then check the box and log the dated line.
  2. Confirm state: executing and move the link to the executing hub bucket.
  3. Graduate the newly answerable "Not yet decided" entries into next steps.
  4. Append the dated line to log.md, then rewrite baton.md.
  5. Run scripts/graph-audit, fix every violation, rerun until it exits zero.

Done when a fresh session tomorrow runs its standup from the baton alone.
